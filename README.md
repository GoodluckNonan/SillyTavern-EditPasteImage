# SillyTavern-EditPasteImage

让**已送出的消息**在编辑时也能直接粘贴或拖入图片。

适用于 SillyTavern 与 TauriTavern（桌面版、Android 版均可）。

---

## 这是干什么的

上游酒馆只有「未送出输入框」能贴图；已送出的消息按铅笔图标编辑时，贴图完全没有反应，只能另外按添加附件。

这个扩展补上那个缺口：在编辑框里 `Ctrl+V` 粘贴，或把图片拖进编辑框，图片就会附加到那条消息。

---

## 怎么用

1. 在聊天室找到要补图的消息，按**铅笔图标**进入编辑。
2. 用下列任一方式放入图片：
   - **粘贴**：光标放在编辑框内，按 `Ctrl+V`（macOS `Cmd+V`）。
     手机是截图后在编辑框长按选「粘贴」。
   - **拖放**：把图片文件拖进编辑框。拖入时编辑框会出现虚线外框，松手即上传。
3. 图片会立刻附加到该消息并存档，消息上直接看得到。
4. 按 **✓** 完成编辑。

未送出的输入框（`#send_textarea`）本来就支持粘贴和拖放，这个扩展不动它的原有流程；
只有开启了自动压缩时，才会顺带把那里的图片也压一遍。

### 下载图片

**点开大图**（点消息里的图片，或那排按钮里的放大镜）之后，图片**右下角**会有一颗圆形**下载**按钮——
它贴在图片自己的边角上，不会飘到图片外面的空白处；按了也**不会**把大图关掉。
画布／画廊里拖出来的图片窗口，同样在右下角有一颗。

另外在触控装置上**长按图片约 0.6 秒**也可以下载，但会先弹出「是否下载这张图片？」让你确认，
所以不会误触。这个手势可以在扩展设置里关掉（默认开）。

**文生图（模型传回的图片）不需要额外设定**：生成结果在酒馆里就是普通的 `message.extra.media`
项目（`source: "generated"`），渲染用的样板与手动机上传的图完全相同，点开大图走的也是同一个灯箱，
所以角标与长按自动适用。生成的**影片**（`<video>`）也一并支援。

> 画廊的缩图牆上只有长按可用，右下角角标要**点开大图之后**才会出现。
> 另外若缩图被包在一个连到原图的连结里，取图时会优先跟随该连结，不会存到缩图。

存到哪去：

- **Android（TauriTavern）**：写进系统的「下载」文件夹；系统不允许直接写入时，会跳到保存对话框让你选位置。
- **iOS（TauriTavern）**：跳出系统分享面板，由你决定存到「照片」还是「文件」。
- **桌面版 / 浏览器**：走浏览器原本的下载行为。

存成功会弹一条「已保存图片：…」的提示并告诉你存到哪；按钮本身会先转圈、成功再打勾。

万一这个装置上所有存档路径都失败（例如 TauriTavern 版本太旧），扩展会**直接把图片丢给系统打开**
（Android 会用系统浏览器开那张图，在那里长按即可另存），并弹一条提示说明原因，不会按了没反应。

> 上游酒馆没有下载按钮，原版的做法是「长按图片 → 用浏览器的原生选单另存」。
> 那条路在 TauriTavern 的行动端 WebView 里不成立，所以这里补上按钮与长按。
> 上游原本那排媒体按钮（放大／Caption／删除）**完全不动**：那排要滑一下才浮出来，
> 藏在里面的下载键不好按，所以下载改放在检视大图的地方。

### 几点要知道

- **放入即生效**：图片在上传成功后就写进消息并存档。所以放完图后按 **✕ 取消编辑**，
  图片仍会留在消息上（取消只放弃文字修改）。要移除请用消息图片上的删除按钮。
- **只处理图片**：粘贴或拖入纯文字时完全不拦截，交给酒馆原生行为。
- **一次多张**：会逐张上传。
- **单张上限**：默认 25 MB，可在扩展设置里调整或整体停用。
- **图片位置**：存到 `user/images/<角色名>/`，与内置添加附件的位置相同。
- 自行撰写的提示文字与讯息，都跟着酒馆的界面语言走（已附简体中文与英文）。

## 自动压缩（可选，默认关闭）

开启后，凡是**超过设定大小**的图片会在上传前自动压缩，压缩完成会弹一个限时提示框
（就是酒馆保存预设时那种绿色提示），报告压缩后的实际大小。

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用自动压缩 | 关 | 总开关。关闭时任何图片都原样上传，等同没有这个功能 |
| 压缩后文件大小上限 | 500 KB | **优先级最高**。图片不超过这个值就完全不动它 |
| 同时限制长边尺寸 | 关 | 只在需要时才缩小尺寸，默认不缩 |
| 压缩后长边最大尺寸 | 2000 px | 上面那项打开后才生效 |
| 最低可接受画质 | 0.5 | 压缩下限，防止为了硬凑体积把图压烂 |

**压缩策略**：优先降低画质去贴合体积上限；只有当画质降到底仍然超标，才会缩小尺寸
（长边限制打开时按该限制缩，否则按比例逐级缩），最低不会低于 320 px。
如果怎么压都达不到目标，会采用能压出的最小结果，并把原图一起保留判断——达不到就不替换、不提示。

**格式**：优先 WebP（体积小且保留透明通道），浏览器不支持 WebP 编码时退回 JPEG，再不行用 PNG。
压缩会重新编码，因此会**清除 EXIF 等元数据**；现代浏览器会依照拍摄方向自动摆正，照片不会歪。

> 提示：压缩不可逆，原始画质无法找回。这项功能默认关闭就是为了不惊动不想被压缩的人。
> 另外它不是无损优化，而是「有损重编码」，对截图/漫画确实会掉一点锐度，介意的话把体积上限调大即可。

## 它到底做了什么

上游的实际情况：

- `public/scripts/chats.js` 里的贴图监听只绑在 `#send_textarea`，编辑框（`#curEditTextarea`）没有。
- 同一文件的原生拖放是 `new DragAndDropHandler('#form_sheld', ...)`，范围仅限送出区。
- 编辑框由 `public/script.js` 的 `messageEdit()` 产生，过程中不处理任何粘贴或拖放事件。

本扩展在 `document` 的**捕获阶段**注册 `paste`、`dragover`、`dragleave`、`drop` 四个监听，
只在事件目标是编辑框时才动作。捕获阶段先于任何绑在 textarea 上的处理器执行，
因此能可靠地吃掉默认行为，也不会让同一张图被处理两次。

- 拖放必须在 `dragover` 呼叫 `preventDefault()`，否则浏览器不会触发 `drop`。
- `drop` 会 `stopPropagation()`，避免酒馆把同一张图又附加到下一条消息。
- 上传走酒馆原生的 `POST /api/images/upload`；若该端点不存在，自动退回 `POST /api/files/upload`。
- `avif`、`svg` 不在酒馆允许的图片格式清单内，会先转成 PNG 再上传。
- 部分 Android WebView 只把图片放在 `text/html` 剪贴簿中，此时会读取其中的内嵌 base64 图片；
  不会发出任何外部网络请求。
- 未送出输入框的压缩走另一条路：监听宿主自己的 `change` 事件（先绑、后处理），
  压缩完把结果写回同一个 `<input type="file">` 并补发一次 `change`，
  因此宿主的附件预览、多档合并等行为完全不用改写。
- 图片下载走两条路，**先试第一条**：
  1. **直接调用 TauriTavern 自己的导出模组** `/scripts/file-export.js` 的 `downloadBlobWithRuntime()`，
     也就是它内建「导出」按钮用的那支函数。它会自己把位元组暂存到 app cache，再叫原生桥接
     写进 Android 的公开下载目录（`MediaStore.Downloads`）或跳 iOS 分享面板。
     这条路上没有 anchor、没有被拦截的机会、也没有同源限制。原版酒馆没有这个档案，
     所以用带保护的动态 `import()`：找不到就安静地走第二条。
  2. **合成一个带 `download` 属性的链接并点击**。桌面版与浏览器照原样下载；
     TauriTavern 行动端也会拦下这种下载、改走它的原生存档流程。
  - 第二条路会把链接收敛到宿主自己的来源。宿主的桥接**默默忽略**跨来源的链接，
    所以遇到「同一个本地服务器换了别名」（`localhost` 与 `127.0.0.1`）时只留路径部分；
    图片真的在别的网站时，先自己抓成 Blob 再交出去。本地图片走同步路径，
    不会因为等待而丢掉「使用者点击」这个前提。
  - 桥接有没有真的接下这次点击是看得出来的：宿主的监听器会呼叫 `preventDefault()`。
    扩展靠这个旗标判断，再加上「是不是行动端 Tauri 壳」来决定要不要提醒。
- **大图灯箱与画廊都没有下载按钮**（上游 `expandMessageMedia()` 与画廊扩展都没做），
  但两者都是同一份文件里的普通节点，所以在容器里补一颗右下角的圆形按钮即可。
  画廊的缩图把原图放在 `data-ngsrc`，所以取图时资料属性优先于 `src`，不会存到缩图。
- **长按下载**只在 `(pointer: coarse)` 的装置上启动，桌面版不装，免得跟选取文字打架。
  长按触发后会吃掉紧接着的那次 `click`，否则灯箱会盖在刚开始的下载上面。

**这个扩展不注入任何界面**：没有工具条、没有缩图预览、没有自制的按钮外观。
消息上的下载按钮塞进酒馆自己的 `.mes_img_controls` 里、沿用它的 `right_menu_button` 样式，
所以外观与原生那颗放大镜一致；灯箱那颗是唯一自绘的外观，因为那个容器里原本什么都没有。
选图本身用内置的添加附件就够了。

**多语言**：设置面板与提示文字走酒馆的 i18n 机制（`i18n/en.json`、`i18n/zh-cn.json`），
跟随酒馆界面语言切换。

## 版本需求与安装

- 开发与测试基准：SillyTavern 前端 `1.18.0`（TauriTavern 同步此版本）
- 纯前端扩展，不需要 Node.js、不需要编译、不需要管理员权限
- 用到的是 `getContext()`、`appendMediaToMessage()`、`ensureMessageMediaIsArray()`、`eventSource`
  这几个长期稳定的 API，较旧的酒馆通常也能运作

### 用 Git URL 安装

1. 打开酒馆的 **Extensions（扩展）** 面板。
2. 点 **Install extension（安装扩展）**。
3. 贴上网址：

   ```
   https://github.com/GoodluckNonan/SillyTavern-EditPasteImage
   ```

4. 出现第三方扩展警告时确认安装。
5. 在扩展清单找到 **Edit Message Paste Image**，确认已启用。
6. **重新载入 App**。

只接受匿名 `http(s)` Git remote，所以请贴仓库根网址，不要用 `/tree/main`、`.git` 或 SSH 网址。

### 手动安装

把这个文件夹整个复制到酒馆的扩展目录：

```
<数据根目录>/default-user/extensions/SillyTavern-EditPasteImage/
```

数据根目录依平台而异：桌面版是酒馆安装目录下的 `data/`；Android 版 TauriTavern 是
`Android/data/com.tauritavern.client/data/`（Android 11 以上需用支持 SAF 的文件管理器才进得去）。

## 数据格式

贴上的图片会成为消息上的一个媒体项目，与内置添加附件产生的结构完全相同：

```json
{
  "extra": {
    "media": [
      {
        "url": "/user/images/<角色名>/1780000000000_ab12cd.webp",
        "type": "image",
        "title": "<角色名> pasted image",
        "source": "upload"
      }
    ],
    "media_index": 0,
    "inline_image": true
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `url` | 图片的相对路径，由服务器返回。扩展名取决于是否压缩：未压缩沿用原格式，压缩后为 `.webp`（或退回的 `.jpg` / `.png`） |
| `type` | 固定 `image`，对应上游 `MEDIA_TYPE.IMAGE` |
| `source` | 固定 `upload`，对应上游 `MEDIA_SOURCE.UPLOAD` |
| `media_index` | 当前显示第几张，指向刚加入的那张 |
| `inline_image` | `true` 时保留消息文字显示 |

文件本体位于 `default-user/user/images/<角色名>/`。因为格式与上游一致，
同样的聊天记录在桌面版 SillyTavern 也能正常显示。
